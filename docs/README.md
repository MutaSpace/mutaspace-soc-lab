# Documentation

This folder contains the main technical documentation for the MutaSpace SOC Lab.

The documentation is written for multiple audiences:

- Beginners learning how SOC labs are built
- Students practicing cybersecurity concepts
- Educators designing hands-on labs
- Recruiters or employers reviewing technical portfolio work
- Cybersecurity professionals interested in Proxmox-based SOC lab design
- MutaSpace learners using the lab for guided training

The goal is to explain not only what was built, but why each decision matters.

---

## Documentation Standard

Each document should be clear enough for someone else to follow, but detailed enough to show real technical understanding.

A strong document should explain:

- What is being built or configured
- Why it matters
- What tools, systems, or services are involved
- What decisions were made
- How the work was validated
- What problems appeared
- What was learned

This lab is not documented as a perfect environment.

It is documented as a real build, including setup decisions, troubleshooting, corrections, and lessons learned.

---

## Lab Documentation Principles

The MutaSpace SOC Lab documentation follows these principles:

1. **Clarity over complexity**  
   Technical work should be explained in a way that learners can understand.

2. **Validation over assumptions**  
   A step is not complete just because it was installed. It should be tested and confirmed.

3. **Troubleshooting is part of the lab**  
   Errors, misconfigurations, and rebuilds are documented because they reflect real infrastructure and SOC work.

4. **Security matters**  
   Public documentation should not expose credentials, private IP details, MAC addresses, tokens, keys, or sensitive screenshots.

5. **Teaching matters**  
   Every major step should help someone understand the concept, not just copy commands.
